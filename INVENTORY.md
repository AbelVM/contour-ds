# Component inventory — Contour

## CSS-level (authoritative)

`dist/contour.components.json` (generated by `tools/build.mjs` from
`tools/lib/inventory.mjs`) lists per block:
- `elements`: `__`-suffixed element classes.
- `variants`: `--`-suffixed variant classes.
- `states`: state classes.
- `tokens`: custom properties the block's rules read (declared tokens).
- `vars`: sheet-defaulted custom properties.
- `inputs`: host-set custom properties (inputs, not retunable tokens).

`tools/check-components.mjs` asserts these resolve in `src/css` and that the
shipped bytes equal a fresh derivation.

## Parts (::part)

Generated at runtime by `ContourBase._applyParts`: every node whose class
matches `c-<block>__<element>` gets `part="<element>"`. Consumers theme
internals via `::part(...)`. No separate registry; the part name is the
element name after `__`.

## Slots (shadow layer)

`SHADOW_SLOTS` in `src/js/wc/shadow.mjs` maps a host tag to its shadow
wrapper's slot list. Named slots follow the element name. Light-DOM wrappers
use slotted content directly (no shadow slots).

## Custom properties (host-set inputs)

Listed as `inputs` in `contour.components.json`. These are values a consumer
sets on the host (e.g. `--chart-1`); they are not retunable tokens and are
not indexed as tokens.

## Gaps (R12-15)

- A single machine-readable file combining CSS tokens/vars/inputs + parts +
  slots per component does not yet exist; `contour.components.json` covers
  CSS only. Shadow parts/slots are documented here but not in the artifact.
