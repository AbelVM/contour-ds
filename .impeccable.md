# CONTOUR — Design Context

> A design system for **spatial interfaces**: routing engines, pedestrian simulators,
> map tooling, and developer-facing geospatial products.

## Audience

| Audience | Context of use |
|---|---|
| Frontend engineers building map/geo UIs | Dense, keyboard-driven, often in a browser tab next to a terminal |
| Product designers prototyping spatial tools | Need tokens they can reason about and hand off |
| GIS / data analysts using a web dashboard | Read-heavy, comparison-heavy, long sessions |
| Technical decision-makers | Scanning a landing page in 20 seconds |

## Use cases

The system serves one product family — spatial tooling — across three kinds of page. Each
surface has its own component set, but they share the tokens, the type scale and the
affordance rules, so a landing page and a dashboard read as the same product.

| Surface | Reader | What it must do | Component set |
|---|---|---|---|
| **Landing page** | A developer deciding in 20 seconds | Make a credible case: precise, fast, honest | logo wall, showcase, metrics, testimonial, pricing, comparison matrix, FAQ, CTA |
| **Documentation site** | A developer mid-task | Get out of the way and answer the question | nav tree, TOC, callout, do/don't, steps, code tabs, install, diff, pager, version picker |
| **Technical dashboard** | An analyst or operator on shift | Carry a lot of numbers and stay scannable | KPI tile, panel, chart frame, filter bar, dense table, activity feed, drawer |

1. **Interactive map tools** — side panels, floating controls, parameter sliders,
   legends, chip readouts, layer switchers. These ride on the dashboard set.
2. **Data views** — isolines, catchments, routes, hex grids; tables, legends, meters.

## Principles

### 1. Affordable means obvious

> "Affordable" in this system means **excellent affordances** — a control looks like what it
> does, and says so before you touch it.

This is the first test a new component has to pass, and it is a *shape* test, not a colour
test. A user who has never seen the system should be able to predict every control's
behaviour from its appearance alone.

- The control shows the **action**, not the state: a copy button copies, a sort control sorts.
- Direction is **drawn**: sort arrows, delta arrows, the copy-to-tick swap.
- State is visible **in the object**: a selected tab is selected, a pressed filter is pressed.
- The cursor is **honest**: `grab` on a handle, `pointer` on a clickable row.
- Nothing hides its hit area: the visible affordance is the clickable affordance.

### 2. Three surfaces, one system

A component belongs to a surface, but the surfaces must not drift apart. The same token
layer, the same type scale and the same affordance rules apply to all three — a pricing
matrix and a dense table use the same border radius, the same hairline and the same
secondary text.

### 3. Colour is a signal, never the message

Roughly 85% of the interface is neutral. Tidal marks action and success, Plasma marks live
data, Clay marks failure. Every state pairs its hue with a shape, an icon or a word, so the
system survives greyscale print, a projector and a reader who cannot separate the hues.

### 4. A chart never asks you to tell two colours apart

Eight categorical hues cannot all be separated by lightness, so a series carries a dash
pattern as well as a hue, and the legend previews that pattern. Every series clears 3:1
against the panel it is drawn on.

### 5. Depth is lightness, not shadow

Shadows are reserved for things that genuinely float — menus, dialogs, toasts, the command
palette. Everything else is separated by surface lightness and a single hairline.

## Brand personality / tone

**"Cartographic instrument."** Not a friendly SaaS, not a neon gamer UI. The
reference is a *precision field device*: a surveying instrument, a sextant, a
topographic sheet. Confident, exact, a little austere, deeply legible.

- **Precise, not decorative.** Every hairline, every tick mark, every mono label
  carries information. Nothing is ornamental for its own sake.
- **Ink over chrome.** Depth comes from surface lightness and a single hairline
  rule, never from stacked drop shadows.
- **Confident restraint.** The palette is 85% neutral. Colour is a *signal*, spent
  sparingly on the things that matter: state, selection, the primary action.
- **Night-shift legible.** Default theme is a deep ink-navy chart, not black. A
  "Daylight" theme exists for daylight desks and printed charts.

## The signature

**Contour lines.** The system's visual signature is the isoline — the closed
curve of equal elevation. It appears as:

- a faint contour field behind the canvas (the "chart paper"),
- **ridgeline dividers** that cut sections like a terrain profile,
- the **contour meter** (progress drawn as nested elevation rings, not a bar),
- the **waypoint mark** (ring + crosshair + pulsing core) used for status dots,
  list markers, and the brand glyph.

One motif, used consistently, is what makes a system recognisable.

The first two are *guide devices* rather than shipped components: the chart paper is masked
with an asset outside the system, and the ridgeline divides the guide's own sections. Both
live in the style guide's stylesheet, so a consumer of `src/` never inherits a dependency they
cannot satisfy. The motif stays; the ownership does not leak.

## Layout treatment

Section bands are **full-bleed** — they run to the viewport edges rather than stopping at the
content column. A band that stops mid-page reads as a misplaced box; a band that runs edge to
edge reads as a deliberate chapter break. The content inside stays aligned to the frame; only
the surface escapes it.

## Type personality

- **IBM Plex Sans Condensed** for display/headings — tight, technical, map-label
  energy. This is the twist on the reference site's plain Plex Sans.
- **IBM Plex Sans** for body/UI.
- **IBM Plex Mono** for data, labels, coordinates, eyebrows, and code.

Two families, one superfamily, contrast by proportion rather than by personality.

## Colour strategy

| Role | Family | Meaning |
|---|---|---|
| Primary | **Tidal** (teal `h≈183`, `#14b8a6`) | Brand, primary action, success, selection |
| Data | **Lumen** (azure `h≈236`) | Secondary data series, info, links in data views |
| Accent | **Plasma** (magenta `h≈359`, `#f20084`) | Hot data, "live" state, editorial highlight — 10% of surface |
| Caution | **Sol** (amber `h≈75`) | Warnings, degraded states, isoline mid-bands |
| Alarm | **Clay** (red-orange `h≈27`) | Errors, destructive actions |

Neutrals (**Basalt**, `h≈230`) are tinted, never pure grey. No pure black, no
pure white. Depth in dark mode = lighter surfaces, not shadows.

The Tidal and Plasma ramps are **anchored on the reference brand colours**:
`--tidal-500` is exactly `#14b8a6` and `--plasma-500` is exactly `#f20084`.
Every other step is derived from those anchors in OKLCH, so the family reads
as the brand hue rather than as an approximation of it.

**Tidal and Plasma carry different jobs and must not be swapped.** Tidal is
*action and state*; Plasma is *highlight*. A highlighted word in the primary
colour reads as decoration; a highlighted word in the accent colour reads as a
signal. Keeping the accent out of the primary's job means the 10% of the
surface that carries it is actually visible.

Data visualisation has its own token layer — `--chart-1…8` for categorical
series, `--chart-seq-1…7` for a single-hue ramp, `--chart-div-*` for a real
midpoint, and `--chart-dash-1…6` for the pattern each series carries. A chart
token maps a value to a *data role*; a semantic token maps a value to *product
meaning*. The two must stay separate: the same magenta is a live-data accent in
the UI and "series 4" in a chart.

## Anti-goals

- ❌ Purple→blue gradient heroes, glass cards everywhere, gradient text on metrics.
- ❌ Identical icon+heading+text card grids repeated for every section.
- ❌ Neon-on-black "cyberpunk" saturation. The reference's `#f20084` on `#0b1114`
  is the *floor* of this palette, not the ceiling.
- ❌ Mono type used as lazy "developer" shorthand for body copy.
- ❌ Floating glass panels without a functional reason to float.
- ❌ A chart that relies on hue alone to separate its series.
- ❌ An icon-only control whose meaning only a regular user would guess.
- ❌ A landing page that reuses the dashboard's density, or a dashboard that
  reuses the landing page's air.
